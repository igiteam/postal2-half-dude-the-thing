## 2. Project concept

**ThingSquareAudio** is a data-driven action/reaction/NPC-state voice system for *The Paranoia Engine*. A voice record belongs to a character, contains an optional **Action** line and/or **Reaction** line, and can be filtered or selected according to the NPC's current state.

The supplied UI concept includes:
- **New Audio Record / Project Name** — create or name an audio-recording project.
- **Record a Character** — choose the speaking character (examples: Blake, North, Burrows, Weldon, Pilot, NPC).
- **Select a Language** — choose a language code (the example is `EN`).
- **Show Character Description** — reveal character-specific reference information.
- **Voice-line table** — browse records by number, character, action, reaction, and NPC state.
- **Add new voice lines** — add a new record.
- **Upload** — associate an audio asset with a record.
- **AI Generate** — optional voice-line/audio generation workflow, subject to the project's chosen tools and rights.

## 3. Filename convention

The example filename is:

`A_Blake_VO_1_ACTION_EN_1234`

Proposed interpretation, based only on the example:
- `A` — record/type prefix (meaning not yet specified).
- `Blake` — character identifier.
- `VO` — voice-over/audio category.
- `1` — record or line number.
- `ACTION` — line slot/type; the table also uses `REACTION`.
- `EN` — language code.
- `1234` — unique suffix or asset identifier (exact generation rule not yet specified).

A matching reaction asset could use `REACTION` in the type segment, but the exact convention should be confirmed before implementing file import/export. Character and language identifiers should be normalized consistently, while the original display names remain human-readable.

## 4. Data model proposed for the `.uc` implementation

A voice record needs, at minimum:
- Stable record ID / line number.
- Character identifier.
- Action text (optional).
- Reaction text (optional).
- NPC state label.
- Language code.
- Action audio asset reference (optional).
- Reaction audio asset reference (optional).

The source table has records where Action is empty, Reaction is empty, or both are present. The implementation must therefore treat Action and Reaction as independently optional fields, not require both.

The NPC State column is currently free-text and includes labels such as `Briefing`, `Alert`, `Confident`, `Injured`, `Scared`, `Alive`, `Critical (dying)`, `Paranoid`, `Hallucinating`, `Panicking`, `Infected`, and `Unhinged`. The supplied spellings and capitalization are preserved in the source table. Before coding, decide whether these labels become a fixed enum/state set or remain data-driven tags.

## 5. Runtime selection concept

A practical runtime flow for the later UnrealScript class:

1. An NPC reports its character ID and current NPC state.
2. An event requests a voice category, such as Action or Reaction.
3. The audio system filters records by character, language, state, and requested category.
4. It selects an eligible record, subject to cooldown and repetition rules.
5. It resolves the corresponding audio asset and plays it.
6. If no matching record or asset exists, it fails safely without interrupting gameplay.

Examples of event/category triggers suggested by the supplied lines:
- **Briefing** — scripted mission dialogue.
- **Combat/action** — enemy spotted, taking fire, cover, movement, enemy KIA, ammunition, weapon use.
- **Squad communication** — follow, hold, cover me, move out, extraction.
- **Condition reactions** — injured, critical/dying, cold exposure, low ammunition.
- **Psychological states** — scared, paranoid, confused, panicking, losing sanity, hallucinating, unhinged.
- **Infection** — infection symptoms and turning-infected dialogue.
- **Helping** — calming another character or providing an item.

These are candidate groupings inferred from the table, not additional source records.

## 6. Integration with the existing AI architecture

The audio system should be a separate subsystem rather than embedding a large dialogue table in `ThingSquadController`.

Suggested responsibility split:
- `ThingSquadController` — coordinates NPC behaviour and emits semantic events.
- `ThingDialogueSystem` or `ThingSquareAudio` — finds and plays the appropriate voice record.
- `ThingTrustSystem`, `ThingFearSystem`, `ThingParanoiaSystem`, `ThingMoraleSystem`, and `ThingInfectionSystem` — update state values and notify the dialogue/audio layer when a meaningful state transition occurs.
- Squad orders and combat logic — request relevant action/reaction lines without directly managing sound assets.

The controller should request dialogue using intent (for example, `EnemySpotted`, `TakingFire`, `OrderFollow`, `BloodTestResult`) rather than hard-coding a particular line number. The audio subsystem can then select an appropriate line for the character, state, and language.

## 7. Playback rules to define before implementation

- **Priority:** scripted briefing and critical gameplay callouts should outrank ambient/bark dialogue.
- **Cooldown:** prevent an NPC from repeating the same line too frequently.
- **Duplicate suppression:** avoid multiple squad members speaking the same generic line simultaneously.
- **Interruption:** define whether a higher-priority line can interrupt a lower-priority one.
- **State validity:** discard or re-evaluate queued lines if the NPC changes state before playback.
- **Fallback:** define behaviour when a character/state/language has no matching record.
- **Randomization:** choose among eligible variants without immediate repetition.
- **Concurrency:** cap simultaneous squad dialogue to avoid audio clutter.
- **Asset validation:** distinguish a text record from a successfully imported/available audio asset.
- **Language fallback:** decide whether missing localized audio falls back to `EN` or remains silent.

## 8. Data quality observations

These are observations about the supplied catalogue, not silent corrections:
- Records **100–134** repeat the same sequence of squad callouts in two consecutive blocks (100–116 and 117–134, with the second block beginning at 117).
- Several state labels appear with variant spelling/capitalization, including `Losing sanity` / `Losing Sanity`, `Hallucination` / `Hallucinating` / `Hallucinations`, and `Loosing sanity`.
- Some source text contains apparent spelling or grammar errors (for example, `I thing I heared something...`, `How many are them?`, and `Can you here it?`). These are retained verbatim in the catalogue.
- The example filename's `A` prefix and numeric suffix `1234` have not been defined beyond their appearance in the example.
- The table does not yet specify audio asset paths, durations, speaker voice variants, subtitle IDs, or playback priority.

For implementation, keep a canonical internal state key separate from the displayed source label. This allows the project to preserve the supplied wording while later mapping spelling variants to one runtime state, if desired.

## 9. Recommended first `.uc` milestone

The first UnrealScript version should be deliberately small:
1. Define a voice-record structure or equivalent data representation supported by the target Postal 2 / Unreal Engine 2 compiler.
2. Store a small test set of records for one character (Blake) and one language (`EN`).
3. Implement lookup by character, requested category, and NPC state.
4. Return the selected text/record and log the intended asset name.
5. Add actual sound playback only after confirming the target engine's sound asset reference and playback APIs.

This first milestone validates the data flow before adding the full catalogue, editor UI, upload pipeline, or AI-generation workflow.

## 10. Questions to settle before coding

- Does `A` mean Action, a project namespace, or a general asset prefix?
- Is the final number a random suffix, a unique database ID, or a take/version number?
- Should Action and Reaction be independently recorded audio files?
- Can one record contain multiple language versions, or is each language a separate record?
- Are NPC states exclusive (one current state) or can an NPC carry multiple simultaneous tags?
- Should state matching allow fallback to `Neutral` or `Alive`?
- Should dialogue selection be random, weighted, sequential, or event-specific?
- Which voice lines are player-controlled Blake dialogue versus autonomous NPC barks?
- What exact audio format and asset naming/path convention does the target Postal 2 build support?
